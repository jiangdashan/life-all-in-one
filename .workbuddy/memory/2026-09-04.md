## 修复导航点击不跳转（v3）

**问题**：移动端、网页端点击导航图标不跳转。

**根因**：init() 中 bindForms() 和 bindEvents() 内有大量 getElementById('xxx').addEventListener() 调用，如果任何一个元素返回 null 就抛错，导致后续代码（包括 document click 事件绑定）不执行，导航失效。

**修复方案**：
1. 提取 bindGlobalClick() 函数，仅绑定导航+quick-action 的 click 事件
2. 在 init() 最前面调用 bindGlobalClick()，确保导航在任何初始化错误之前就绑定好
3. 用 try-catch 包裹 bindForms() 和 bindEvents()，单个失败不影响其他

**教训**：事件委托应优先绑定在 document 上，且必须在所有可能出错的初始化代码之前执行。

## 修复清空功能不生效（v8）

**问题**：清空全部按钮点击后数据没清掉，刷新后数据恢复。

**根因（双重问题）**：
1. **绑定时机问题**：清空按钮的 click 绑定在 bindEvents() 末尾，如果 bindEvents 内部前面的 getElementById('xxx').addEventListener 抛错（元素不存在），清空按钮不会被绑定 → 点击没反应
2. **异步删除时序问题**：清空时 deleteRemoteXxx 是异步操作，用户刷新后 pullAllRemote 立即拉取远程数据，此时远程可能还没删完，merge 函数把远程数据合并回来 → 数据恢复

**修复方案**：
1. 把清空按钮绑定移到 bindGlobalClick() 中（init 最前面执行，不受 bindEvents 错误影响）
2. 提取 handleClearAll() 独立函数
3. 清空时设置 state.clearedAll=true 标记，saveState 保存
4. pullAllRemote 检查 clearedAll 标记：如果为 true，不执行 merge，而是继续清空远程所有表，完成后清除标记
5. normalizeState 保留 clearedAll 标记

**验证**：node --check 语法通过，标签闭合完整，无重复 today 声明。

**教训**：
- 关键操作按钮的绑定不能放在可能有错误的函数末尾，必须用事件委托提前绑定
- 异步删除 + 刷新拉取的时序问题需要用标记解决，不能依赖异步操作完成

## 彻底修复清空功能（v9）

**用户反馈**："清空数据后再次刷新页面，数据会恢复；移动端无法清空数据"

**诊断发现远程数据表实际记录数（关键证据）**：
习惯打卡 370 条、收支 30 条、健身 19 条、日程 15 条、饮食 10 条、待买 4 条、书影音 4 条、物品存储 1 条，合计 453 条。
→ 证明清空时**远程数据从来没被删除过**，刷新后 pullAllRemote 全部拉回。

**三个根因**：
1. **删除依赖 remoteId 但 remoteId 没持久化**
   - handleClearAll 用 `if(r.remoteId) deleteRemoteXxx(r.remoteId)`
   - pushXxx 里 `dbAdd(..., function(rid){ if(rid) rec.remoteId = rid; })` 只改内存**不 saveState**
   - 刷新后 remoteId 全部丢失 → 清空时几乎删不掉任何远程记录
   - 习惯打卡压根没有 remoteId 概念（pushHabit 只 add 不存 id）
2. **移动端点击检测失败**
   - 按钮内是 `<svg><use href="#i-trash"/></svg>`
   - 移动端 WebView 中 SVG 元素的 `closest()` 不可靠 → `event.target.closest('#clearSamplesBtn')` 返回 null
   - 原生 `confirm()` 在移动端 WebView 也可能被拦截
3. **习惯打卡数据无限膨胀**
   - `pushHabit` 每次打卡无条件 `dbAdd` 新增一条，从不 update → 累积到 370 条

**修复方案**：
1. 新增 `clearAllRemoteTables(cb)`：对 9 张表直接 fetchAll → 逐条 deleteRecord，**完全不依赖 remoteId**
2. 新增 `showConfirm(opts)`：自定义确认弹窗替代原生 confirm（含 CSS，按钮 ≥44px）
3. `bindGlobalClick` 改用 `findAncestor`（parentElement 遍历）+ `contains()` 兜底，不依赖 SVG 的 closest
4. `saveStateQuiet()` 防抖保存，pushMoney 回调持久化 remoteId
5. `habitRemoteIndex` 索引（习惯名+日期 → recordId），pushHabit 改为 upsert（有则 update 无则 add）

**验证方法（本次新增，很关键）**：
- 用 Node 模拟 mockDb 测试 clearAllRemoteTables：453 条全部删除 ✓
- 用 Node 模拟 DOM 树测试点击检测：按钮/span/svg/use 四种场景全部命中 ✓
- node --check 语法验证 ✓
- 复核远程 9 张表剩余记录数均为 0 ✓

**执行动作**：用 batch_delete_database_records.py 清空了远程 453 条历史脏数据。

**教训**：
- 批量删除绝不能依赖业务记录的 remoteId，应该直接查表删
- 异步回调里改了 state 必须持久化，否则刷新即丢
- SVG 内部元素的 closest() 在移动端不可靠，要用 parentElement 遍历 + contains 兜底
- 修复前先查远程真实数据状态，不要只看代码逻辑

## 修复"每刷新一次数据 +1"（v11）

**问题**：页面每刷新一次，数据就 +1（实际是翻倍：3→6→9→12）。

**根本原因**：`isKeptLocal()` 判断逻辑错误。v10 为了跨设备清空，把判断改成：
`!item.sample && (createdAt > lastClearedAt)`
但 lastClearedAt 默认 0，而 createdAt 是 Date.now() 恒 > 0，导致**所有非 sample 记录（含已同步的）都被判为"本地未同步"**。于是 merge 时：
`state.records = filter(非该类型).concat(remoteRecords).concat(_unsynced)`
里 `_unsynced` 包含了所有已同步记录，与 remoteRecords 重复 → 每次刷新数据翻倍。

**修复**：`isKeptLocal` 改回 `!item.sample && !item.remoteId`。跨设备清空逻辑本就由 `applyRemoteClear`（init 时按 lastClearedAt 过滤 state）独立完成，不需要 isKeptLocal 重复判断时间戳。

**验证**：
- 8 个 merge 类型（money/plan/fitness/shopping/media/diet/storage/mood）翻倍回归：2/2/2 全部通过 ✓
- 离线新增保留 ✓、同步完成不重复 ✓、跨设备清空后本地新增保留 ✓
- node --check 语法通过 ✓
- 线上页面与本地一致 ✓

**关键教训（新增第 8 条铁律）**：
- **isKeptLocal 只判断"是否本地新增未同步"（!remoteId），不要混入时间戳判断**。时间戳判断（清空信号）应由独立的 applyRemoteClear 处理，职责分离。混在一起会因 lastClearedAt=0 的默认值导致所有记录都被误判为未同步 → 数据翻倍。

## 修复"web 端数据有一部分没同步到移动端"（v14）

**问题**：用户反馈 web 端输入数据保存后，有一部分数据没同步到移动端。

1. **单次失败 → 全局永久离线（致命）**：`dbAdd`/`dbUpdate`/`dbDelete` 的 `.catch` 里都调用 `goLocalOnly()`。只要任何一次写入/更新/删除失败（网络抖动、单条字段问题），`LOCAL_ONLY=true`，此后**所有 push 全部静默 return**，数据只存 localStorage，再也不上云 —— 这正是"web 端存了、移动端看不到"。

3. remoteId 提取只兜底 `result.id || result._id`（SDK 契约未明说 addRecord 返回字段名）。

**修复**：
- 移除 add/update/delete 三处 `.catch` 里的 `goLocalOnly()`，改为只记 console.warn；`LOCAL_ONLY` 只用于 SDK 环境不可用。现在 `goLocalOnly` 在整个文件里**零调用点**。
- 新增 `syncPendingRecords()`：init 拉完远程后，把本地所有 `!sample && !remoteId` 的 records（7 种 type 分发对应 push）+ mediaItems + 习惯打卡（按 habitRemoteIndex 判断远程缺失）重推一次。

- `dbAdd` 的 remoteId 提取加固为 `result.id || result._id || result.record_id || result.recordId`。
- init 挂载：`pullAllRemote(ok)` 成功后调 `syncPendingRecords`，n>0 时延迟 2.5s 再 saveState+renderAll+toast 提示。

**验证**：`node --check` 通过；提取 `syncPendingRecords` 真实运行 6 个场景全 PASS（未同步全补传 / 已同步+示例不补传 / 60秒退避 / 书影音+打卡补传 / 远程已有不重复 / 离线不补传）；发布 v15，线上与本地 diff 一致。
