1. **renderPeriod 内 `var rec=records.find(...)` 漏了 `state.` 前缀** → ReferenceError "records is not defined"。**铁律**：从 IIFE 外复制代码到 IIFE 内时，**所有非形参的局部变量必须改成 `state.x`**，否则会被 TDZ 抛错且不显示行号。
2. **click handler 必须放在 `const action=closest('[data-action]')` 早返回之前** —— 没有 data-action 的元素（state/chip/counter 按钮）会让 handler 提前 return，导致点击无效。**铁律**：非 data-action 的元素必须用 `event.target.closest(...)` 在早返回前处理；data-action 元素才放后面 `const type=...` 块。
3. **linkedom 不支持 form.elements**：用 `Object.defineProperty(Object.getPrototypeOf(form), 'elements', {get(){...}})` polyfill（打到 HTMLElement 实际原型，不是 window.HTMLFormElement —— linkedom 把所有元素扁平成 HTMLElement，window.HTMLFormElement 是摆设类）。
4. **表单 `Object.fromEntries(new FormData(...))` 仍依赖 elements polyfill**：FakeFormData 内部 `form.elements` 取不到时要回退到 `form.querySelectorAll('[name]')`，并支持 radio/checkbox 跳过未选/checkbox 布尔语义。
5. **monkey patch `app.state.records.push = ...`** 看似捕获 push，实际 push 不一定被调到（如果 throw 被 catch）；同时 `Object.defineProperty(records, 'push', ...)` 后未捕获到 throw 会导致后续断言全部丢失。**铁律**：调试时优先用直接调用 `app.addRecord(...)` 验证，比 monkey patch push 更可靠。
6. **analyzePeriod 的 avgCycle 应只算已结束周期**：`starts` 数组最后一个元素通常是「当前正在进行的周期」，不应进入 `cycles` 计算。

8. **DB 备份脚本硬编码路径是另一台机器的盘符**：本机是 `D:/workbuddy/...` 不是 `E:/workbuddy/...`。已统一修正。

## 13:4x v26 修复：历史经期周期智能预测 + 首末自动补全

**问题**：用户要求"要支持根据历史经期周期推测下次周期；历史周期可以通过保存当次首日末日自动补全当次周期"。v24 实现存在 2 个缺陷：

1. **`periodLens` 只算 isPeriodDay 标记** —— 用户如果只标首日+末日（不每天勾 isPeriodDay），avgPeriod 会永远算成默认 5 天，因为找不到 isPeriodDay='Y' 的记录。
   - **修复**（line 2109-2128）：新算法加"末日标记优先 + 首末跨度数兜底"：`spanDays = endDay-startDay+1`；先查本周期内最后一条 `isEndDay='Y'` 的日期作为末日，若无则用「下个首日前一天或今天」；len 优先级 `periodDayCount > 0 ? periodDayCount : (2<=span<=15 ? span : 0)`。

2. **currentEnd 用硬编码算式**（line 2226）：`shiftDate(-1,new Date(a.starts[a.starts.length-2]))` —— 当 starts 只剩 1 个历史周期时，下标 -2 = undefined，shiftDate 会崩；同时取的是倒数第二个 starts 的前一天，不是当前周期的末日。
   - **修复**：改用 `periodEnds[a.periodEnds.length-1]`。

3. **analyzePeriod 不返回每个周期的末日** —— renderPeriod 的周期历史、用品统计、情绪统计都临时计算末日，逻辑散落且可能不一致。
   - **修复**：analyzePeriod 增加 `periodEnds:[]`，每个元素对应周期的实际末日（末日标记 / 下个首日前一天 / today）。renderPeriod 全部消费这个数组。

4. **状态卡没有样本数说明** —— 用户看不出"平均 28 天周期"是基于几次历史算出来的。
   - **修复**（statusHtml）：在 avgCycle/avgPeriod 后加 `<small style="opacity:.6;font-weight:400">· N 次样本</small>`。

**关键设计选择**：v26 决定**未闭合周期不计入历史均值**（avgCycle / avgPeriod / cycles）。理由：当前周期还没结束，现在算平均会被拉低（用户 9-06 才首日，周期通常 28 天）。v24 老测试期望 `[3,2,1]` 包含未闭合周期，新算法只 `[3,2]`，是**算法主动调整**，不是 bug。把 v24 老测试改为 `OK_v26(未闭合周期不计入均值)`。

**另外修 cycles 算法**：v24 老实现 `closedStarts=starts.slice(0, starts[last]===today?-1:undefined)`，只在 last 是 today 时才排除 —— 大多数实际场景（用户在月中而不是今天）会算错。新算法 v26 `closedStarts=starts.slice(0,-1)`（starts 长度≥2 时），简单稳健。

## 14:09 v27 修复：经期同日多条重复脏数据 + starts 重复

**问题**：用户反馈"周期历史里 3 条相同的无效数据；新记了一次首+末但显示 2 天，周期错误"。查找后定位 2 个 bug：

### Bug 1：`addRecord('period', date, data)` 总是 push 新记录，不合并同日
- 用户每天多次保存（首日 / 经期中 / 末日），每次都生成独立 record
- `state.records` 累积多条同日期记录
- 如果用户每次都勾首日，`analyzePeriod` 的 `starts` 数组就有同日重复日期
- UI 周期历史循环渲染 N 行相同 "进行中"，看着像"3 条无效数据"

### Bug 2：合并用 `Object.assign({}, old, new)` 被空字符串覆盖
- 用户第一次保存：data = `{isStartDay:'Y', isPeriodDay:'Y', isEndDay:''}`
- 用户第二次保存：data = `{isStartDay:'', isPeriodDay:'Y', isEndDay:''}`（表单默认空）
- `Object.assign({}, old, new)` 用 new 覆盖 old → `isStartDay` 从 'Y' 变成 ''
- 连锁：`isPeriodDay`='Y' 被覆盖、`discharge`='' 覆盖之前的'粘稠'、症状/出血量 也被冲掉
- 结果：merged record 的 data 全是空，只有最后一次的数值（pad/moodScore 因为是数值所以保留）

### 修复
1. **`addRecord('period', date, data)` 改为"同日合并"语义**（line 1606-1633）：
   - 查找同日已存在 period 记录（state.records.find）
   - 合并：旧 data 是 base，新 data 中"非空"字段（!= '' && != null && != undefined）才覆盖
   - 数组字段（symptoms）union 去重
   - 复用 existing.remoteId → upsert 到云端（pushPeriod 不再新建云端行）
   - 如果同日不存在，走原路径 push 新 rec
   - 重复条数仅 1，invalid 重复消失

2. **`analyzePeriod` starts 用 `Array.from(new Set(...)).sort()` 去重**（line 2117）：
   - 历史脏数据：2026-09-06 同日有 3 条 `isStartDay=Y` 的记录
   - 去重后 starts = ['2026-09-06']（1 个）
   - 周期历史显示一行，无重复

### 新教训（v29）
- **HTML `[hidden]` 属性会被作者 CSS `display:flex/grid/block` 静默覆盖**（同 specificity 后者胜）。**铁律**：toggle 隐藏的元素如果是 `display:flex` 等自定义布局，**必须显式写 `.xxx[hidden]{display:none}`**，否则用户看到的"按钮没反应"实际是 hidden 翻转了但视觉不变。

**关键教训（v30 教训）：**
- **union 模式比 replace 模式更安全**：宁可本地多，绝不本地少（用户红线第 3 条）
